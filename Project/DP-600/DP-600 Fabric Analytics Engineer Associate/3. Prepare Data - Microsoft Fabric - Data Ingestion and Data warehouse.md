### Lab - Microsoft Fabric Data Warehouse - Building the Dimension Date Table

```sql
-- 1. First, create the date dimension table.
CREATE TABLE [DimDate] (
    [OrderDate] [date] NULL,
    [DateYear] [varchar](6) NULL,
    [DateMonth] [varchar](12) NULL,
    [DateMonthNumber] [varchar](6) NULL
);

-- 2. Create a stored procedure that populates the date dimension table.
CREATE PROC AddDate
AS
BEGIN
    DECLARE @StartDate date;
    DECLARE @EndDate date;

    SET @StartDate = '2011-05-31';
    SET @EndDate = '2014-06-30';

    WHILE @StartDate <= @EndDate
    BEGIN
        INSERT INTO DimDate
        SELECT
            @StartDate,
            DATEPART(yyyy, @StartDate),
            DATENAME(MONTH, DATEADD(MONTH, DATEPART(mm, @StartDate), -1)),
            DATEPART(mm, @StartDate);

        SET @StartDate = DATEADD(day, 1, @StartDate);
    END
END;

-- 3. Execute the stored procedure to populate the table.
EXEC AddDate;
```

### Lab - Microsoft Fabric Data Warehouse - SQL - GROUP BY

```sql
-- 1. Count the number of sales for each product.
SELECT
    ProductID,
    COUNT(SalesOrderID) AS SalesCount
FROM FactSales
GROUP BY ProductID
ORDER BY SalesCount;

-- 2. Filter the grouped results to return only products
--    with more than 100 sales.
SELECT
    ProductID,
    COUNT(SalesOrderID) AS SalesCount
FROM FactSales
GROUP BY ProductID
HAVING COUNT(SalesOrderID) > 100
ORDER BY SalesCount;

-- 3. Combine WHERE, GROUP BY, and HAVING to find products
--    with more than 100 sales during 2012.
SELECT
    ProductID,
    COUNT(SalesOrderID) AS SalesCount
FROM FactSales
WHERE YEAR(OrderDate) = 2012
GROUP BY ProductID
HAVING COUNT(SalesOrderID) > 100
ORDER BY COUNT(SalesOrderID);
```

## 3.2 What is Microsoft Fabric

Azure vs Fabric

**Fabric** is more focus on analytics and data warehousing, while Azure is a broader cloud platform that includes a wide range of services for computing, storage, networking, and more. Fabric provides a unified experience for data engineers and analysts to ingest, prepare, and analyze data in a collaborative environment.

**Azure** is a cloud computing platform and service created by Microsoft for building, testing, deploying, and managing applications and services through Microsoft-managed data centers. It provides a wide range of cloud services, including those for computing, analytics, storage, and networking.

Fabric inlcude Power BI, Data Factory, Synapse, and Data Lake, which are all integrated into a single platform for data analytics and business intelligence. Azure provides a broader set of services that can be used for a variety of purposes beyond data analytics, such as virtual machines, databases, AI services, and more.

**OneLake** is a unified data lake that allows organizations to store and manage all their data in a single location. It provides a scalable and secure environment for storing structured, semi-structured, and unstructured data. OneLake is designed to work seamlessly with Microsoft Fabric, enabling users to easily ingest, prepare, and analyze data from various sources.

## 3.3 Microsoft Fabric Terms

### 3.3.1 Fabric Terms

**Experience**: A collection of related services and tools that work together to provide a specific functionality or capability within Microsoft Fabric. Examples include the Data Engineering experience, the Data Science experience, and the Business Intelligence experience.

**Workspace**: A collaborative environment within Microsoft Fabric where users can create, manage, and share data projects, datasets, reports, and dashboards. Workspaces provide a centralized location for teams to work together on data-related tasks.

**Item**: A specific object or resource within a workspace, such as a dataset, report, dashboard, or dataflow. Items can be created, modified, and shared with other users within the workspace.

**Capacity**: A measure of the resources allocated to a workspace or experience within Microsoft Fabric. Capacity determines the amount of storage, processing power, and other resources available for data projects and tasks. Capacities can be assigned to workspaces to ensure that they have the necessary resources to perform their functions effectively.

### 3.3.2 Data Engineering

**Fabric Data Warehouse**: A cloud-based data storage and analytics solution within Microsoft Fabric that allows users to store, manage, and analyze large volumes of structured and semi-structured data. The Fabric Data Warehouse provides a scalable and secure environment for data warehousing, enabling users to perform complex queries, aggregations, and transformations on their data.

**T-SQL**: A variant of the SQL (Structured Query Language) used in Microsoft Fabric for querying and managing data within the Fabric Data Warehouse. T-SQL includes additional features and extensions specific to Microsoft Fabric, allowing users to perform advanced data manipulation and analysis tasks.

**Lakehouse**: A data architecture that combines the benefits of data lakes and data warehouses, allowing organizations to store and analyze both structured and unstructured data in a single platform. The Lakehouse architecture enables users to perform advanced analytics, machine learning, and business intelligence tasks on their data.

**Notebook**: An interactive environment within Microsoft Fabric where users can create, edit, and run code, visualizations, and analyses. Notebooks support multiple programming languages, such as Python, R, and SQL, allowing users to perform data exploration, analysis, and visualization tasks in a flexible and collaborative manner.

### 3.3.3 Data Factory

**Connector**: A pre-built integration within Microsoft Fabric that allows users to connect to various data sources, such as databases, APIs, and cloud services. Connectors enable users to easily ingest and access data from different systems, facilitating data integration and analysis tasks.

**Data pipeline**: A series of data processing steps within Microsoft Fabric that define the flow of data from source to destination. Data pipelines can include data ingestion, transformation, and loading tasks, allowing users to automate and orchestrate their data workflows.

**Dataflow Gen2**: An enhanced version of dataflows within Microsoft Fabric that provides improved performance, scalability, and functionality for data transformation and preparation tasks. Dataflow Gen2 allows users to create reusable data transformation logic, enabling efficient data processing and analysis.

### 3.3.4 Real Time

**Eventhouse**: A real-time data processing and analytics service within Microsoft Fabric that allows users to ingest, process, and analyze streaming data from various sources. Eventhouse enables organizations to gain insights from real-time data, supporting use cases such as monitoring, alerting, and predictive analytics.

**Eventstream**: A continuous flow of data generated by events or actions within a system, application, or device. Eventstreams can be ingested and processed in real-time using Microsoft Fabric's Eventhouse service, enabling organizations to analyze and respond to events as they occur.

**KQL Database**: A database within Microsoft Fabric that supports querying and analyzing data using Kusto Query Language (KQL). KQL is a powerful query language designed for real-time data exploration and analysis, allowing users to perform complex queries, aggregations, and visualizations on their data.

## 3.8 Review of the Data Warehousing Fundamentals

**OLTP vs OLAP**

| Concept  | Meaning                       | Purpose                                   |
| -------- | ----------------------------- | ----------------------------------------- |
| **OLTP** | Online Transaction Processing | Handles day-to-day transactions           |
| **OLAP** | Online Analytical Processing  | Analyzes large amounts of historical data |

**Memory:**
`OLTP = Run the business`
`OLAP = Analyze the business`

A **data warehouse** is primarily designed for **OLAP workloads**.

---

**Data Warehouse**

A **data warehouse** is a **persistent data store designed for analytical workloads**.

It stores historical data for:

- Querying large datasets
- Performing analysis
- Aggregating numerical data
- Analyzing trends
- Supporting reporting and BI

Traditional data warehouse architecture separates:

- **Compute** → runs queries and database operations
- **Storage** → persists the data

A data warehouse commonly exposes a **SQL endpoint** for SQL queries.

---

**Fact Table**

A **fact table** stores measurable business events and numerical values.

Examples:

- SalesAmount
- Quantity
- Cost
- Profit
- Revenue

Example:

```text
FactSales
---------
DateKey
ProductKey
CustomerKey
Quantity
SalesAmount
```

**Remember:**
`Fact = What happened + measurable values`

---

**Dimension Table**

A **dimension table** provides descriptive information and context for facts.

Example:

```text
DimProduct
----------
ProductKey
ProductID
ProductName
Category
Brand
```

Dimensions allow analysis from different perspectives:

- Sales by product
- Sales by customer
- Sales by country
- Sales by date

**Remember:**
`Dimension = Describes the facts / provides context`

---

**Star Schema**

A **star schema** contains:

- One central **fact table**
- Multiple **dimension tables**

```text
             DimDate
                |
                |
DimProduct -- FactSales -- DimCustomer
                |
                |
             DimStore
```

**Remember:**
`Fact + Dimensions = Star Schema`

---

**Business Key / Alternate Key**

The **business key**, also called the **alternate key**, comes from the **source system**.

Example:

```text
ProductID = P1001
```

`ProductID` is the business/alternate key.

---

**Surrogate Key**

A **surrogate key** is generated within the data warehouse/model.

It is commonly an integer and uniquely identifies a dimension row.

```text
ProductKey = 101
ProductID  = P1001
```

Therefore:

```text
ProductID  → Business / Alternate Key
ProductKey → Surrogate Key
```

**Memory:**

- **Business key** → comes from source system
- **Surrogate key** → generated for the warehouse

---

**Microsoft Fabric Architecture**

Microsoft Fabric uses **OneLake** as a unified storage layer.

```text
                Microsoft Fabric
                       |
        +--------------+--------------+
        |              |              |
      T-SQL          Spark            KQL
        |              |              |
        +--------------+--------------+
                       |
                     OneLake
                       |
               Unified Storage
```

**Key idea:**

`OneLake = Storage`

`T-SQL / Spark / KQL = Ways to process or query data`

---

**OneLake**

**OneLake** is the **unified storage layer for Microsoft Fabric**.

It provides a central storage foundation that different Fabric workloads and engines can work with.

---

**T-SQL, Spark and KQL**

**T-SQL**

```text
T-SQL → SQL queries → Relational / Warehouse analytics
```

**Spark**

```text
Spark → Notebooks → Distributed data processing
```

**KQL**

```text
KQL → Kusto Query Language → Analytical querying
```

---

**Power BI vs Data Warehouse**

Power BI is mainly used for:

- Semantic modeling
- Data analysis
- Visualization
- Reports
- Dashboards

A data warehouse provides **persistent analytical storage**.

```text
Source Systems
      ↓
Data Transformation
      ↓
Data Warehouse / Lakehouse
      ↓
Semantic Model
      ↓
Power BI
      ↓
Reports & Dashboards
```

```text

Fact → Measures

```

**Six things to remember:**

1. **OLTP = transactions; OLAP = analytics**
2. **Fact tables = measurable business events**
3. **Dimension tables = descriptive context**
4. **Star schema = fact + dimensions**
5. **Business key = source; surrogate key = generated**
6. **OneLake = Fabric's unified storage layer**
