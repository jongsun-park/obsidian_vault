**Tips and tricks to help accelerate your learning:**

1. Some fields don't exist as single database columns!  They are calculated rather than stored.  The most common example of this is document subtotal.  Only the final total is stored for an invoice (for example) and there isn't a subtotal available.  You need to do a formula such as `T0.[DocTotal] + T0.[DiscSum] + T0.[DpmAmnt] - T0.[TotalExpns] - T0.[VatSum]` to find the value.
2. In SQL Management Studio, make a new query and use SELECT TOP 100 * FROM OINV.  This type of query allows you to see the entire table to take a closer look at values available.  Saying SELECT TOP 100... limits the results, so if you put SELECT * FROM OINV and you have 100,000 invoices you don't get 100,000 rows.  Likely to explore the data you simply need a few rows to look at what data is available.  So find a table you want to investigate and do a `SELECT TOP 100 * FROM <TABLE>` then scroll around and look at the results.
3. Search Google for example queries, there are hundreds, if not thousands of example queries for SAP Business One.  Just search and you will likely find some example or a place to start.  In the coming lectures you will then be able to break that query down, understand it and make your own.  This is a great way to start getting comfortable with SQL queries!
4. Use the SAP Business One SDK Reference Manual.  I will attach it to this lecture.  It's a great resource to see options for specific fields, to see keys and related tables and to search for various column names for more information.
5. Use "NO LOCK" so that you don't lock the tables as you run your queries so you can do "FROM OCRD WITH (NOLOCK)" in your FROM clause for each table and this will stop SQL from exclusively reading the table.  It is known as a "dirty" read but since you don't need the data down to the second it's better to let other users continue to function while you are potentially pulling hundreds of thousands of rows.  You don't want to impact system performance.  So use NO LOCKS!
6. NULL and blank are not the same thing.  If you get a NULL value then you can't perform certain operations.  Something like NULL \* 1 does not equal 0 it equals NULL and then when you add 1 + 0 + NULL + 100 it will equal NULL.  If you face a potential scenario where the value might not exist you should consider using the COALESCE() function.  Like COALESCE(<my number>,0) which will return a zero if the <my number> column reoslves to NULL.  Then your summary or mathematical operations can still continue properly.  I cover this in a future lecture but it's smart to get familiar with the concept early.

Practice, practice, practice!  If you do not use the new skills you have learned, then you will lose them.  Make time to tackle the queries you want to generate.  It will feel like a struggle while you are learning, but the solutions you come up with will benefit you in the future.  Day by day your skill will grow and by the time you know it, you will be a Jedi Master.
